# mrcrop Reference Guide

`mrcrop` extracts data representing an individual user experience from one or more Oracle extended SQL trace files that contain multiple experiences (such as those generated by connection-pooled applications or broad tracing windows).

Each output file created by `mrcrop` is a **completely self-contained, valid Oracle trace file**, containing the file preamble, database release banner, all relevant cursor definitions (`PARSING IN CURSOR`), execution plans (`STAT` lines), and bind values needed to analyze that isolated experience.

---

## 1. Synopsis and Global Options

### Synopsis
```bash
mrcrop [options] command [args] [file ...]
```
- If `file` is omitted, `mrcrop` processes all `*.trc` files in the current working directory (`.`).
- If `file` is a directory, `mrcrop` processes all `*.trc` files in that directory.

### Global Options
| Option | Description |
| :--- | :--- |
| `--ofile=string` | Specify the destination path/name for the output trace file. (Used when extracting a single experience). |
| `--silent` | Suppress printing the names of generated output files. |
| `--verbose=level` | Verbose output level (`0` = quiet, `1` = file names, `2` = diagnostic details). |
| `--recursive`, `-R` | Recursively plunge into subdirectories. |
| `--exclude=regex` | Exclude files matching the given regular expression pattern. |
| `--stop-on-exception` | Halt processing immediately if an error occurs in any input file. |
| `--initrc` / `--noinitrc`| Respect or ignore default `.rc` files. |

## 2. The Six Cropping Commands

### 1. `mrcrop island` (The Oceans–Islands–Rivers Algorithm)
Used for **connection-pooling applications** where an application server keeps a database connection open continuously.
- **Ocean**: Any `SQL*Net message from client` call with duration $\ge Z$ seconds (think time between separate user requests).
- **River**: Any `SQL*Net message from client` call with duration $< Z$ seconds (network latency between dbcalls during the *same* user request).
- **Island**: A contiguous block of database calls and "rivers" representing a single end-user interaction.

```bash
mrcrop island [-z=seconds] [--start-time=ISO8601] [--end-time=ISO8601] [file ...]
```
**Options**:
- `-z=number`, `--thinktime=number`: Think-time threshold in seconds. Default: `1.0`. Any client wait $\ge z$ terminates an island.
- `--count=number`: Limit the number of islands extracted.
- `--start-time=date-time`, `--end-time=date-time`: Accept or reject entire islands based on whether any part falls within this time window.

**Example**:
```bash
# Crop trace file into individual user experience files using 1.0s think-time threshold:
mrcrop island -z=1.0 app_session.trc

# The generated files are saved into a subdirectory named after the trace file:
# app_session/app_session-16.trc
# app_session/app_session-3326.trc
```

### 2. `mrcrop datetime` (Time-Interval Cropping)
Crops performance data (PARSE, EXEC, FETCH, WAIT, etc.) strictly falling between a specified start and end timestamp in ISO 8601 format. Cursor preambles and execution plans outside the window are preserved if referenced.

```bash
mrcrop datetime [--start-time=date-time] [--end-time=date-time] [file ...]
```
**Options**:
- `--start-time=ISO8601`: Exclude performance data before this timestamp (e.g., `2023-05-16T08:00:00`).
- `--end-time=ISO8601`: Exclude performance data after this timestamp. Default: `9999-12-31T23:59:59`.

**Example**:
```bash
# Crop trace to the exact 5-minute interval during a reported incident:
mrcrop --ofile=incident.trc datetime \
  --start-time=2023-05-16T08:15:00 \
  --end-time=2023-05-16T08:20:00 \
  production.trc
```

### 3. `mrcrop sqlid` (SQL ID Boundary Cropping)
Extracts contiguous trace data starting with the earliest call for `--start-sqlid` and ending with the latest call for `--end-sqlid`.

```bash
mrcrop sqlid --start-sqlid=sqlid --end-sqlid=sqlid [file ...]
```
**Arguments**:
- `--start-sqlid=sqlid`: SQL ID (or the keyword `XCTEND` for transaction boundary) that marks the start of the experience.
- `--end-sqlid=sqlid`: SQL ID (or `XCTEND`) that marks the end of the experience.

**Example**:
```bash
# Isolate a business workflow starting with a lookup query and ending with a commit:
mrcrop sqlid --start-sqlid=4gn68gurpt1xp --end-sqlid=XCTEND batch_run.trc
```

### 4. `mrcrop experience` (Experience ID Marker Cropping)
Extracts experiences delimited by explicit application instrumentation markers written to the trace file via `DBMS_LOG.KSDWRT` or `DBMS_SYSTEM.KSDWRT`:
`*** EXPERIENCE ID:(...)`

```bash
mrcrop experience [--id=string] [file ...]
```
**Options**:
- `--id=string`: Create a standalone trace file only for experiences whose ID has `string` as a prefix. If omitted, extracts all experiences found.

**Example**:
```bash
# Isolate experience marked with ID "CHECKOUT-1092":
mrcrop experience --id=CHECKOUT-1092 webapp.trc
```

### 5. `mrcrop transaction` (Transaction Boundary Cropping)
Splits trace files at `XCTEND` lines (commit or rollback operations). Each output file corresponds to a single database transaction.

```bash
mrcrop transaction [--start-time=date-time] [--end-time=date-time] [file ...]
```

**Example**:
```bash
# Split trace file into standalone transaction trace files:
mrcrop transaction financial_postings.trc
```

### 6. `mrcrop linerange` (Line-Number Range Cropping)
Extracts performance calls between two specific physical line numbers within the trace file.

```bash
mrcrop linerange [--start-line=n] [--end-line=n] [file ...]
```
**Options**:
- `--start-line=number`: Starting line number in input file.
- `--end-line=number`: Ending line number. Default: `0` (end of file).

**Example**:
```bash
# Crop lines 50000 to 75000 identified via mrskew or mrwhen:
mrcrop --ofile=section.trc linerange --start-line=50000 --end-line=75000 large.trc
```

## 3. Recommended Workflow: Scoping Before Profiling

When analyzing a large or multi-hour trace file:
1. **Identify Islands with `mrskew`**:
   ```bash
   mrskew --rc=island.rc large_file.trc
   ```
2. **Crop the Target Island**:
   If the largest island starts at line 3326:
   ```bash
   mrcrop island -z=1.0 large_file.trc
   # Inspect generated file in large_file/large_file-3326.trc
   ```
3. **Profile the Cropped File**:
   ```bash
   mrskew large_file/large_file-3326.trc
   ```
   Now the profile represents the user's active response time with 100% precision, completely free of idle client think time!
